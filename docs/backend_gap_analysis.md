# Backend Gap Analysis (for the backend team)

**Goal:** close every gap below so the agent layer can wrap the backend as a *plain, safe, fully-working REST API* — the agent must never have to compensate for missing backend behavior in code that the agent layer owns. Items are ordered by impact to the agent's security/correctness story.

| # | Issue | Files (confirmed) | Fix | Priority |
|---|---|---|---|---|
| A1 | **No `GET /me`** (or profile/mfa/password-confirm routes). `TokenResponse.user` is `{id,email,role}` only; schemas `UserResponse`, `UserUpdate`, `PasswordChange`, `PasswordResetConfirm` are defined but unused. Agent can't "get the user's detail." | `schemas/auth.py:83,55,71,128`; `modules/auth/router.py` (no /me) | Add `GET /auth/me` → `UserResponse`; `PUT /auth/me` (body `UserUpdate`); `PUT /auth/me/password` (`PasswordChange`); `POST /auth/password-reset/confirm` (`PasswordResetConfirm`). | **P0** |
| A2 | **No free-text product search.** `GET /catalog/products` filters only `merchant_id/category_id/status`. Design expects `?q=` (+ price range/currency). Agent's primary use case unblocked. | `modules/catalog/router.py:118-130`; `modules/catalog/service/base.py:94-116`; `modules/catalog/service/implementation.py` | Add `q`, `price_min`, `price_max`, `currency` params to router + service + a LIKE/FTS search + DB index. Return matches with variants. | **P0** |
| A3 | **Idempotency does not actually deduplicate completed requests.** `get_idempotency_dependency` sets `request.state.skip_execution` + `cached_response`, but **no route reads them** — handlers re-run the service and `return response_data`. The agent doc §3.3 relies on this as the backstop. | `core/idempotency.py:92-99` (sets flags); `modules/orders/router.py:28-71` (ignores flags) | Minimal: each mutating handler short-circuits when `request.state.skip_execution` and returns the cached `(status, body)` as a `JSONResponse`. **Preferred:** implement idempotency as middleware that runs *before* routing and returns the cached body / 409s in-progress, so no handler can forget. | **P0** |
| A4 | **IDOR: `GET /payments/{payment_id}` has no auth** (no `current_user` dependency). Anyone can read any payment. | `modules/payments/router.py:64-78` | Add `current_user` dependency + ownership/scoping (buyer ⇒ own order's payment; merchant/admin ⇒ their orders). | **P0** |
| A5 | **No payout endpoints.** `MerchantPayoutAccount` model + `MerchantPayoutAccountCreate/Update/Response` schemas + `payout_worker.py` exist, but there's no router/service for payout accounts or `POST /merchants/{id}/payouts`. | `models/merchant_payout_account.py`; `schemas/merchants.py:76-119`; `workers/payout_worker.py` | Add payout-account CRUD + `POST /merchants/{id}/payouts` (requires Idempotency-Key + MFA step-up per design doc); `GET /merchants/{id}/payouts`; service layer that writes `payout_hold`/`payout_release`/`payout_paid` ledger entries. | **P1** |
| A6 | **No KYC review endpoint.** `PATCH /admin/merchants/{id}/kyc` missing; `kyc_status` is set at creation only. | `modules/merchants/router.py` | Add `PATCH /admin/merchants/{merchant_id}/kyc` (platform_admin) updating `kyc_status` + reason; idempotent. | **P1** |
| A7 | **Rate-limiter middleware does not decode the JWT** ("we would decode the token here… for now, skip"). `user_id` is always `None`, so only the 100 req/min **per-IP** bucket applies. The MCP server shares one gateway IP. | `core/rate_limit.py:77-83` | Decode the bearer JWT in middleware and apply per-user limits in addition to per-IP (mirror the checkout endpoint's explicit `sliding_window_allow`). | **P1** |
| A8 | **`ProductVariantResponse` omits `quantity_available`** (model has it). Agent can't answer "is it in stock?" before add-to-cart. | `schemas/catalog.py:67-76` | Add `quantity_available: int | None` to the response and populate it in the catalog impl. | **P2** |
| A9 | **Payment processing is stubbed.** `process_payment` fakes `status='success'` and never calls Paystack / creates a real provider reference. The webhook flow is the real source of truth for "paid". | `modules/payments/service/implementation.py:42-100` | Implement a `PaymentProvider` interface (design doc §5.4) for Paystack; `process_payment` creates `status='initialized'` + provider reference; the **webhook** (not the agent) flips it to `success`. (Bigger item; the agent's `initiate_checkout`→`PaymentCapturePanel`→poll flow depends on this being real.) | **P1** |
| A10 | **No `merchant_staff` assignment model.** Orders/Fulfillment routers say "would check a merchant_users junction table." Staff access is effectively unenforced. | `modules/orders/router.py:180-184`; no `merchant_users` model | Add `merchant_users(merchant_id, user_id, role)` junction; enforce staff scoping in orders/fulfillment/stores/merchants. | **P2** |
| A11 | **DB dialect mismatch.** Local `backend/.env` = MySQL (`mysql+asyncmy://`); design doc + `.env.example` = PostgreSQL; `Product` model uses a PG-only `postgresql_where` index. Local dev path is inconsistent. | `backend/.env:1`; `models/product.py:47`; `db/types.py` | Standardise local dev on PostgreSQL (use `.env.local.example` / Neon), matching the design doc and the PG-only index. (The agent layer is HTTP-only so this is mainly a dev/CI correctness issue.) | **P2** |

**Two non-blocking clarifications** (document, don't block):
- Refund caller: doc §3.2 table says `platform_admin` only; code allows `merchant_owner`/`merchant_staff`. Decide and make consistent.
- Path naming: doc refers to `GET /merchants/{id}/ledger`; real read path is `/ledger/balance/{merchant_id}` + `/ledger/entries`. The MCP tool maps to the latter.
